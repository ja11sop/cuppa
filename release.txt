# Cut a cuppa release (master is protected — prefer the Actions buttons below).
#
# Full guide with diagrams:
#   docs/modules/ROOT/pages/contributing/release.adoc
#   (Antora: Contributing → Cutting a release)

# --- Once: Trusted Publishing ----------------------------------------------------
#
# 1. GitHub → Settings → Environments → `pypi` with required reviewers.
# 2. PyPI → project cuppa → Publishing → trusted publisher:
#      Owner: ja11sop  Repository: cuppa  Workflow: release.yml  Environment: pypi

# --- Each release (happy path) ---------------------------------------------------
#
# Prerequisites: open cycle on master (`cuppa/VERSION` is X.Y.Z.dev, CHANGELOG has entries).
#
# 1. Actions → release → Run workflow → action: **prepare**
#      Opens a PR that runs finish_release (VERSION + dated CHANGELOG, impact:none).
# 2. Merge that PR when CI is green.
# 3. Actions → release → Run workflow → action: **publish** (leave tag blank)
#      Builds from master tip, creates the GitHub Release + tag via API, deploys GitHub
#      Pages (documentation workflow), then waits for approval on the `pypi` environment.
# 4. Approve the `pypi` deployment.
#
# Do not push a v* tag by hand unless you mean to; publish from master is the supported path.
# Re-run publish for an existing tag: action **publish** with tag=vX.Y.Z.
# `git push origin vX.Y.Z` still triggers the same publish jobs (escape hatch).

# --- Opening the next cycle (after a release lands) ------------------------------
#
# On a PR branch when the next workstream starts:
#   python -m scripts.start_release X.Y.Z
#
# Local finish_release is still available if you prefer a hand-rolled prepare PR:
#   python -m scripts.finish_release
#   git commit -am "Release $(cat cuppa/VERSION)"
