= Extending cuppa
:description: Custom methods, dependencies, profiles, and plugins

== Module auto-registration

Drop a Python module under one of these packages with classmethods `add_options` and/or `add_to_env`:

* `cuppa/methods/`
* `cuppa/dependencies/`
* `cuppa/profiles/`
* `cuppa/variants/`
* `cuppa/toolchains/`
* `cuppa/project_generators/`

`cuppa.modules.registration` loads them when cuppa starts.

Optional: `init_env_for_variant(sconscript_exports)` for per-variant setup.

== setuptools entry points

Third-party packages can register plugins without forking cuppa:

|===
| Group | Purpose

| `cuppa.method.plugins` | Extra env methods (cuppa ships HTML/Bitten test report methods here)
| `cuppa.profile.plugins` | Extra profiles
| `cuppa.dependency.plugins` | Extra dependencies
|===

== Factories

|===
| Factory | Module

| `cuppa.location_dependency(name, …)` | Location / header libraries
| `cuppa.package_dependency(name, …)` | Registry packages
| `cuppa.conan_deps(…)` / `cuppa.conan_dependency(…)` | Optional Conan 2 consumer (see xref:dependencies/conan.adoc#conan-2-consumer-optional[Conan packages])
| `cuppa.profile(name)` | Named profile class factory
|===

Pass custom classes into `cuppa.run(dependencies=[…], profiles=[…])`.

When writing custom `env.Command` / `Action` helpers, avoid multi-part shell strings such as `cd … && …`.
Use a Python action with subprocess `cwd=` (or `cuppa.utility.command.run`) so parallel builds stay correct.
See xref:methods.adoc#custom-commands-and-working-directories[Custom commands and working directories].

== Pip dependency plugins

Third-party packages can ship a named dependency that Cuppa discovers automatically via `cuppa.dependency.plugins`.
After `pip install`, consumers list the dependency **by name** in `default_dependencies` — no `cuppa.run(dependencies=[…])` entry is required.

Two complete examples live under `examples/`. Both register the dependency name `fmt`; install **one** of them in a given environment (they are alternative supply chains for the same name).

|===
| Example | Supply chain | Package

| `examples/cuppa_fmt_plugin/`
| `location_dependency` + build static lib from source
| `cuppa-fmt`

| `examples/conan_fmt_plugin/`
| Conan 2 / SConsDeps (`cuppa.conan_dependency`)
| `cuppa-conan-fmt`
|===

=== Location-based plugin (`cuppa-fmt`)

Subclass `cuppa.location_dependency`, override `__call__` to compile sources and append `STATICLIBS` — the same pattern as in-tree helpers such as Quince’s date library:

[source,python]
----
import cuppa

class fmt(
    cuppa.location_dependency(
        'fmt',
        sys_include='include',
        location='https://github.com/fmtlib/fmt/archive/refs/tags/12.2.0.zip',
        linktype='static',
    )
):
    def __call__(self, env, toolchain, variant):
        super(fmt, self).__call__(env, toolchain, variant)
        sources = env.Glob(self.local_sub_path('src/format.cc'))
        sources += env.Glob(self.local_sub_path('src/os.cc'))
        library = self.build_library_from_source(env, sources, 'fmt')
        env.AppendUnique(STATICLIBS=[library])
----

`pyproject.toml` entry point:

[source,toml]
----
[project.entry-points."cuppa.dependency.plugins"]
fmt = "cuppa_fmt:fmt"
----

Install and use:

[source,sh]
----
pip install -e path/to/examples/cuppa_fmt_plugin
----

[source,python]
----
import cuppa

cuppa.run(
    default_variants=['dbg'],
    default_dependencies=['fmt'],
)
----

Cuppa fetches the archive on first use (kept under the dependencies and downloads roots). Pass `--offline` only after the tree is already cached.

=== Conan-based plugin (`cuppa-conan-fmt`)

The Conan example wraps `cuppa.conan_dependency` instead of fetching sources:

[source,python]
----
import cuppa

FmtConan = cuppa.conan_dependency(
    'fmt',
    requires=['fmt/12.1.0'],
)
----

[source,toml]
----
[project.entry-points."cuppa.dependency.plugins"]
fmt = "cuppa_conan_fmt:FmtConan"
----

The consumer still needs Conan 2 on `PATH` for installs (unless you use `generators_folder` with a pre-run install).
Details: xref:dependencies/conan.adoc#conan-2-consumer-optional[Conan packages].

The same entry-point group works for any dependency type (location, package, Conan, or a future SCons Tool wrapper); only the class behind the entry point changes.

== Custom dependency sketch

[source,python]
----
class my_dependency(object):
    @classmethod
    def add_to_env(cls, env, add_dependency):
        add_dependency('my_dependency', cls.create)

    @classmethod
    def create(cls, env):
        return cls(env)

    def __init__(self, env):
        self._env = env

    def __call__(self, env, toolchain, variant):
        env.AppendUnique(CPPPATH=['#/include'])

    def name(self):
        return 'my_dependency'
----

Optional storage hooks (see xref:dependencies/managing.adoc#remove-dependencies[Removing dependency trees] and xref:dependencies/extending.adoc[Writing your own dependencies]):

* `storage_paths(env, selection)` — declare owned trees under the dependencies root so
  `--list-dependencies` / `--remove-dependencies` can find them without retrieving.
* `storage_clean(env, selection)` — when present, remove only selection-scoped products and
  leave the extract; return `{targets, extract}` (or `None` if unsupported). Source Boost uses
  this for b2 stage / `bin.<abi>` cleans.

== Custom profile sketch

Profiles are callables applied like dependencies but geared at small flag sets:

[source,python]
----
class sanitizers(object):
    def __call__(self, env, toolchain, variant):
        env.AppendUnique(CCFLAGS=['-fsanitize=address'])
        env.AppendUnique(LINKFLAGS=['-fsanitize=address'])
----

== Contributing changes to cuppa itself

Validation, versioning, and how to cut a release are documented under
xref:contributing.adoc[Contributing] (including Mermaid diagrams of the prepare / publish flow).

Quick local gate:

[source,sh]
----
flake8 cuppa
pylint -E cuppa
pytest -m unit
pytest -m integration
----

`pytest -m integration` requires a {cpp} compiler (typically `g{plus}{plus}`).
Smoke-test against `examples/minimal/` after installing your working tree (`pip install -e .` or `PYTHONPATH`).

Lint settings live in xref:linting.adoc[Linting].
Integration scenarios live under xref:integration-tests.adoc[Integration tests].
Agent-oriented checklists remain in the repository `AGENTS.md` / `release.txt`.
