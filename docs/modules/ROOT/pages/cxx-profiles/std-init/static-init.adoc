= std::init: static and constant initialization (`static_runtime_init`)
:description: std::init rule static_runtime_init — non-local runtime initializers

include::partial$cxx-profiles/attribute-markers.adoc[]

== What this rule checks

Variables with **static** or **thread** storage duration must be **constant initialized**
when they have initializers. Runtime calls (functions, non-constexpr expressions) in non-local
initializers are rejected.

Static storage is zero-initialized by default; marking it `{cxx-a-uninit}` is handled under
xref:cxx-profiles/std-init/markers.adoc[Markers and initializers] instead.

== Example violation

From `examples/profiles/std-init-violations/static_runtime_init.cpp`:

[source,cpp]
----
int seed();
int RuntimeGlobal = seed(); // runtime call at namespace scope
----

== Expected Clang diagnostic

[source]
----
error: non-local variable 'RuntimeGlobal' requires constant initialization under profile 'std::init'
----

== Resolutions

* Use **constexpr** initialization where possible.
* Move runtime setup into a function-local `static` inside a function (dynamic initialization
  rules differ for block scope) or an explicit init routine called before use.
* Split compile-time constants from values computed at startup and document ordering.
* **Suppress** only when you rely on platform-specific dynamic init you cannot refactor yet.
