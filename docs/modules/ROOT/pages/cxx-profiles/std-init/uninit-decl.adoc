= std::init: uninitialized declarations (`uninit_decl`)
:description: std::init rule uninit_decl — variables left uninitialized without the uninit marker

include::partial$cxx-profiles/attribute-markers.adoc[]

== What this rule checks

Automatic and local objects, aggregate members, and unions must either be **initialized** or
explicitly marked `{cxx-a-uninit}` to acknowledge indeterminate storage. Partial initialization
of aggregates still leaves indeterminate members.

== Example violation

From `examples/profiles/std-init-violations/uninit_decl.cpp`:

[source,cpp]
----
void automatic_uninitialized()
{
    int automatic; // no initializer, no [[uninit]]
    (void)automatic;
}
----

== Expected Clang diagnostic

[source]
----
uninit_decl.cpp:…: error: variable 'automatic' must be initialized or marked '[[uninit]]' under profile 'std::init'
----

Union objects use a dedicated message shape:

[source]
----
error: variable '…' of union type must be initialized under profile 'std::init'
----

== Resolutions

* **Initialize** the object: `int value = 0;` or aggregate initialization `{ … }`.
* **Mark intentional indeterminate storage**: `{cxx-a-int-buffer-uninit}` and ensure later
  writes precede reads (see xref:cxx-profiles/std-init/uninit-read.adoc[reads before
  initialization]).
* **Suppress** locally when an external API fills the storage before any read (document why
  in the `justification:` string).
