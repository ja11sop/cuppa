= std::init: constructor initialization (`ctor_uninit_member`)
:description: std::init rule ctor_uninit_member — constructors must initialize members and bases

include::partial$cxx-profiles/attribute-markers.adoc[]

== What this rule checks

A user-provided constructor must initialize every non-static data member (via a
member-initializer or default member initializer) unless the member is marked `{cxx-a-uninit}`.
Direct non-virtual **base subobjects** must also be initialized — bases cannot carry
`{cxx-a-uninit}`.

Assignments in the constructor **body** do not satisfy the rule; reads of `{cxx-a-uninit}`
members before those assignments are still flow-checked.

== Example violations

From `examples/profiles/std-init-violations/ctor_uninit_member.cpp`:

[source,cpp]
----
struct with_member {
    int value_;
    with_member() {} // 'value_' not initialized
};

struct with_base : base {
    with_base() {} // base subobject not initialized
};
----

== Expected Clang diagnostics

[source]
----
error: constructor does not initialize member 'value_' under profile 'std::init'
error: constructor does not initialize base class 'base' under profile 'std::init'
----

== Resolutions

* Add **member-initializers**: `with_member() : value_( 0 ) {}`.
* Provide **default member initializers** on members that always start with a known value.
* Mark rarely-used members `{cxx-a-uninit}` when indeterminate startup is intentional, and
  ensure no read precedes your first write.
* Initialize bases in the mem-initializer list: `with_base() : base{ … } {}`.
* **Suppress** for legacy types under incremental adoption (prefer fixing constructors).
