= Integration tests
:description: Cuppa pytest integration suite — scenarios, generated sconstruct/sconscript, and expectations

Cuppa's pytest integration suite lives under `tests/integration/`.
Each scenario documented here shows the **`sconstruct` / `sconscript` the test generates** (or uses), the cuppa command, and what is asserted.

== Running the suite

[source,sh]
----
pytest -m integration
----

Requires a C++ compiler (`g++` preferred).
Optional tools (`clang`, `gcov`, AsciiDoc) cause individual tests to skip with a log line when absent.

Every `run_cuppa()` call also passes `-D`, `--offline`, and a default `--toolchains=` selection.
Override the default family with `CUPPA_TEST_TOOLCHAIN=gcc|clang|vc` (used by CI to smoke the suite per toolchain).
For Clang, pin the standard library with `CUPPA_TEST_ARGS=--clang-stdlib=libstdc++` or
`CUPPA_TEST_ARGS=--clang-stdlib=libc++` (explicit flags in a test override the env extras).

Linux CI matrices three cells: `gcc`, `clang` + `libstdc++`, and `clang` + `libc++`.
Each Linux integration job also installs Conan 2 so xref:integration/test-conan.adoc[`test_conan`] runs (not skipped).
Windows CI uses MSVC (`vc`) via `windows-latest` (Conan not installed there yet).

== Shared fixture

Most method tests copy `tests/fixtures/dummy_project/` into a temporary directory, then overwrite the build scripts.
That tree provides apps, libraries, nested sources, pass/fail tests, benches, and sample data (templates, Markdown, SCSS, and so on).

Default `sconstruct` used by many tests:

[source,python]
----
import cuppa

cuppa.run(default_variants=['dbg'])
----
