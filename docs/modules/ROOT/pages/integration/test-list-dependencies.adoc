= `test_list_dependencies` — list dependency trees
:description: Cuppa integration test documentation for test_list_dependencies


== What is tested

With planted trees under a private `--storage-root`, `--list-dependencies` reports them as a
hierarchical table (including an `unreferenced` section) without removing anything, and
`--list-format=json` emits parseable objects with a `tree` and flat `entries`. The first listing
upgrades missing inventory sizes to exact (with a notice that measuring may take a while); a
second listing reuses the cache. A default location dependency whose tree is absent appears
as `missing` (including in JSON `missing_count` / entries) without aborting the listing.
`--list-scope=referenced` and `unreferenced` filter which sections appear (including
in JSON `scope` / `entries` / `tree`). The deprecated `--list-dependencies-scope` alias still
works.

A local location tree under `--storage-root` is listed without stamping `used_by`. A subsequent
`--dbg` build records `last_used_source=resolve` and the project path in `used_by`.

A second fixture plants GitHub release extracts, a Boost source archive, a GitLab package tree,
and matching files under `downloads/`. Verbose listing then checks:

* archive identities (`github.com/fmtlib/fmt`, `boost`) with version children
* LOCATION download URLs reconstructed from encoded folder names
* `[D]` only where a regenerating archive exists under downloads (GitHub tag with a zip;
  Boost `.tar.gz` or `.zip` depending on platform; GitLab toolchain archive leaf — not the
  GitLab registry URL on the version row)
* the `[D]` footer text
* JSON `has_download`, `download_path`, and `remote_location` on those entries

== Generated files

The dummy project with the default `sconstruct`, plus planted trees under
`<storage>/dependencies/` (VCS-style folders, GitLab `tool_variant/package/version`, and encoded
HTTP archive folders). The verbose scenario also plants `<storage>/downloads/` (flat archive
files and `packages/<package>/<version>/*.{tar.gz,zip}`) and a `sconstruct` that declares a GitLab
`boost_package` so resolve can supply a registry URL.

== Commands

[source,sh]
----
cuppa -D --offline --list-dependencies --storage-root=<storage>
cuppa -D --offline --list-dependencies --list-scope=referenced --storage-root=<storage>
cuppa -D --offline --list-dependencies --list-scope=unreferenced --storage-root=<storage>
cuppa -D --offline --list-dependencies --list-format=json --storage-root=<storage>
cuppa -D --offline --list-dependencies --list-format=verbose --storage-root=<storage>
cuppa -D --offline --list-dependencies --exact-sizes --storage-root=<storage>
----

== Expectations

Text output includes `Dependencies in`, a `DEPENDENCY` header, the planted tree name, and
`unreferenced`. The first listing may print `Measuring exact sizes…` when inventory sizes are
missing; a second listing reuses the cache. JSON parses with `entries`, `size_bytes`, `state`, `tree`, and
`dependencies_root`. The planted tree remains on disk after listing.

Verbose output includes `LOCATION`, grouped archive short names, `[D]` on cached download
leaves only, and the downloads footer. JSON entries for those leaves carry `has_download` /
`download_path` / `remote_location` as appropriate.
