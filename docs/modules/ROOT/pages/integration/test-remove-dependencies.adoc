= `test_remove_dependencies` — remove dependency trees
:description: Cuppa integration test documentation for test_remove_dependencies


== What is tested

With planted trees under a private `--storage-root`:

* An unknown registry name exits non-zero and lists known dependency keys.
* Removing a location dependency deletes only the selected branch folder and reports a sibling
  `@feature_x` tree as left for other selections; `-n` leaves both folders in place.
* With `--develop`, a configured develop working copy is never deleted.
* A GitLab package dependency removes only the selected toolchain's
  `tool_variant/package/version` tree and leaves another toolchain's sibling.

== Generated files

The dummy project with a custom `sconstruct` declaring `widget` and/or `boost_package`, plus
planted folders under `<storage>/dependencies/` (and a develop tree outside storage for the
develop-skip case).

== Commands

[source,sh]
----
cuppa -D --offline --remove-dependencies=widgt --storage-root=<storage>
cuppa -D --offline -n --remove-dependencies=widget --storage-root=<storage>
cuppa -D --offline --remove-dependencies=widget --storage-root=<storage>
cuppa -D --offline --develop --remove-dependencies=widget --storage-root=<storage>
cuppa -D --offline --dbg --remove-dependencies=boost_package --storage-root=<storage>
----

== Expected outcome

Successful removals print an announce line, a compact REMARK table, optional leftovers and
develop skips, a freed-space summary, and a `--list-dependencies` verification hint. Dry-run
uses “Would remove”. Unknown names fail before any delete.
