= `test_configure_conf` — configure.conf persistence
:description: Cuppa integration test documentation for test_configure_conf


== What is tested

`--save-conf` writes project settings to `configure.conf`; `--show-conf` loads and displays the
merged effective settings. `--show-global-conf` reports `~/.cuppaconfig` alone (project overrides
do not appear on that equivalent `cuppa -D` line).

== Generated files

Copied from the dummy project, then:

=== `sconstruct`

[source,python]
----
import cuppa

cuppa.run(default_variants=['dbg'])
----

=== `sconscript`

[source,python]
----
Import('env')
env.BuildTest('hello_test', 'tests/hello_test.cpp')
----

== Commands

[source,sh]
----
cuppa -D --offline --toolchains=gcc --dbg --save-conf
cuppa -D --offline --toolchains=gcc --show-conf
cuppa -D --show-global-conf
----

== Expectations

`configure.conf` exists after the first run; the second run succeeds and reflects the saved `dbg`
setting. The global-show run succeeds and prints workstation keys from `~/.cuppaconfig` without
project-only flags such as `--dbg`, announces CONFIGURE mode, and (when pins are present) a
`N registry latest mappings` judgement-style tree under the equivalent line.
