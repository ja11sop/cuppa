= Boost (source / Boost.Build)
:description: Built-in boost dependency — b2, use_libs, patched home, vs boost_package

The built-in `boost` dependency builds or uses a Boost tree via Boost.Build (`b2`).
It is registered as the name `boost`. For prebuilt Boost from a GitLab registry, use
xref:dependencies/gitlab.adoc#boost-package[`boost_package`] instead — same `use_libs([...])`
call shape, different supply chain.

== Options

* `--boost-home` / `--boost-location`
* `--boost-version` / `--boost-latest`
* `--boost-build-always`, `--boost-verbose-build`, `--boost-verbose-config`
* `--boost-patched` (deprecated alias: `--boost-patch-boost-test`)

== Latest version and offline CI

When you use Boost without an explicit `--boost-version=`, `--boost-home=`, or
`--boost-location=`, Cuppa resolves a version in this order:

1. `--boost-latest` — check https://www.boost.org/releases/latest/ when online, then use that
   release (or fall back to the compiled-in default if the check fails).
2. A stored `boost_latest_version` value (see below).
3. The compiled-in default from Cuppa's `current_boost_release()`.

Cuppa does **not** scrape boost.org on every Boost use. Without `--boost-latest`, a project that
simply `BuildWith('boost')` prefers the stored value, then the compiled-in default.

=== Remembered latest (`boost_latest_version`)

After a resolve that selects a latest/default version, if that version's archive is present under
`--downloads-root` (fresh download or cache hit) and the version is **strictly higher** than any
value already stored, Cuppa upserts:

* `boost_latest_version = X.Y.Z`

into either:

* the project `configure.conf`, when `downloads_root` is under the project (`sconstruct`) directory, or
* `~/.cuppaconfig`, when downloads are shared outside the project

so the remembered latest follows the same sharing as the download cache.

A failed scrape's fallback is never written. A lower version never overwrites a higher stored
value. Explicit `--boost-version=` / `--boost-home=` / `--boost-location=` remain authoritative and
do not update this key.

=== Online then offline CI pattern

A common layout is:

1. Online, parallel: download and build (optionally with `--boost-latest` after a Boost release).
2. Offline, serial: `cuppa … --offline --test` against the same `--downloads-root`.

Persistence makes step 2 reuse the version from step 1 instead of falling back to an older
compiled-in default. Keep `--downloads-root` consistent across both passes so the archive and the
stored key stay aligned (project-local downloads with project conf, or a shared downloads root with
`~/.cuppaconfig`).

== Using libraries

[source,python]
----
env.BuildWith('boost').use_libs(['system', 'filesystem'])
# or the older env-method form:
env.AppendUnique(STATICLIBS=env.BoostStaticLibs(['system', 'filesystem']))
# or
env.AppendUnique(DYNAMICLIBS=env.BoostSharedLibs(['system']))
----

`use_libs([...])` matches registry packages such as `boost_package`, so you can switch supply
chains by changing only the `BuildWith` name. It builds (or reuses) static libraries via
`BoostStaticLibs` and appends them to `STATICLIBS`. Aliases such as `BoostStaticLib` /
`BoostStaticLibrary` also exist for compatibility.

When a dependency offers linkable libraries, prefer exposing `use_libs(libs, depends_on=[])`
on the instance returned by `env.BuildWith(...)`. Package dependencies already do this;
location-only (header) dependencies typically omit it.

== Clean and patched homes

Source Boost keeps two homes under one extract: `clean/` (default) and `patched/`.
`--boost-patched` is a **selection axis**, like `--dbg` / `--rel`: build,
`--remove-dependencies`, and `--purge-dependencies` use only the active home. Products under
the other home are reported as leftovers, not deleted. Use a second invocation with the other
flag (or omit it) to clean that home too.

`--remove-dependencies=boost` uses `storage_clean` to delete only the selected b2 **stage** and
matching Boost.Build toolset directories — not the whole extract. Details and sample output:
xref:dependencies/managing.adoc#remove-dependencies[Removing dependency trees].
