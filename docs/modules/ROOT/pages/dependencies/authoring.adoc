== What belongs here vs Publishing

**Authoring** is where you define *how Cuppa learns about a dependency*: factories, plugins,
`storage_paths` / `storage_clean`, and packaging a dependency so others can
`pip install` it and list it in `auto_enable_dependencies`.

**Publishing** is where you *ship build artefacts* of libraries you already know how to
build: GitLab uploads, cascade nest publishes, amend/external CMake, Conan `export-pkg`,
and publisher working copies.

Some Publishing pages also talk about how to *build* a nest before upload (cascade plan,
external CMake). That overlap is real; a follow-on pass will move “how to construct a
dependency factory / plugin” examples firmly under Authoring — including anonymised worked
examples patterned on large package trees (for example a fat registry package with many
`use_libs`) — and keep Publishing focused on registry / publisher workflows. See the
Authoring follow-ons in `design/plans/dependencies-docs-four-hubs.md`.

For declaring and consuming existing kinds, see
xref:dependencies/using.adoc[Using dependencies].
For shipping artefacts, see
xref:dependencies/publishing.adoc[Publishing dependencies].
