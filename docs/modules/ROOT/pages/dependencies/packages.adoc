= Package dependencies
:description: package_dependency overview — consume registry archives

`cuppa.package_dependency()` downloads a prebuilt archive from a package registry and lays it
out under `--dependencies-root` per toolchain / variant / architecture.

Today the supported `package_manager` is GitLab generic packages — see
xref:dependencies/gitlab.adoc[GitLab packages] for authentication, lookup overrides,
`version="latest"`, and the Boost package extension. Publishing Cuppa-built libraries is a
different workflow: xref:packages.adoc[Publishing packages].

[source,python]
----
import cuppa

MyPkg = cuppa.package_dependency(
    'mypkg',
    package_manager = 'gitlab',
    registry = 'https://gitlab.example.com/api/v4/projects/123',
    package = 'mypkg',
    version = '1.2.3',
)

cuppa.run(
    dependencies = [ MyPkg ],
    # Register above; auto-BuildWith in every sconscript (same factory or MyPkg.name()):
    default_dependencies = [ MyPkg ],
)
----

Pin `version` to a concrete string, or use `version = 'latest'` (or omit / `None`) to resolve
the newest version **published in that registry** for the package name at configure time.
Offline reuse of that pin is documented under
xref:dependencies/gitlab.adoc#version-latest[Registry latest].
A missing package or an unresolved `latest` fails during configure, before compile.

== Develop vs package downloads

`--develop` affects *location* develop paths and package develop flags where defined.
It does *not* invent a local substitute for a missing registry archive: the matching package
must exist in the registry or already be cached under the dependencies and downloads roots.
