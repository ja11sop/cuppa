= Reclaiming storage
:description: Reclaim dependency trees — remove, purge, wipe, force-wipe overview

Choose how aggressively to reclaim trees under `--dependencies-root` (and archives under
`--downloads-root`). This page is the map: how the flag families relate, dependency
filters, a shared example inventory, and a glance table of common filters.

Detailed semantics and worked examples (why + dry-run reports) live on the action pages.

[#two-reclaim-paths]
== Two reclaim paths

Cuppa offers two different ways to reclaim disk. Mixing them up is the usual source of
surprise.

=== Context-scoped: remove → purge → wipe

`--remove-dependencies`, `--purge-dependencies`, and `--wipe-dependencies` are one related
ladder. Each step is more aggressive than the last, and **all three** only touch caches that
match the **current invocation** — the toolchain(s), variant(s), and location-match flags of
this cuppa run (the same flags that decide where cuppa writes). They also require
**project-used** names from this project's `sconstruct` / `BuildWith` graph.

That makes them ideal when you are reclaiming *this* project's current caches from *this*
checkout with the flags you normally build with. It makes them awkward when the tree you
want to delete was produced under another project, another toolchain, or a one-off
integration-test layout: you would need a matching `sconstruct` and the right
`--toolchains` / variant flags before a filter can hit those leaves.

In this guide, that toolchain / variant / location-match scope is the **active context**.
It is **not** the same as a filter **selector** (`[gitlab]`, `[source]`, <...>), which only
restricts which dependency *type* a name matches — see
xref:#dependency-types-and-selectors[Dependency types and selectors].

[cols="1,2,4"]
|===
| Step | Flag family | Relative to the previous step

| 1
| xref:dependencies/managing/removing.adoc[Remove]
| Deletes this context's **build products** (for source Boost: bin/build outputs under
  the extract) or the selected package tree; **downloads stay**; the extract may remain

| 2
| xref:dependencies/managing/purging.adoc[Purge]
| Everything remove does, **plus** the matching download archive; the **extract stays**
  (no re-fetch)

| 3
| xref:dependencies/managing/wiping.adoc[Wipe]
| Deletes the **whole extract** and its download — a clean slate; the next online build
  re-fetches
|===

For source Boost, remove and purge leave headers and `b2` in the extract; wipe removes that
extract entirely. For GitLab packages, remove already takes the selected package tree, so
purge vs wipe differs mainly in framing (both clear the tree and, for purge/wipe, the
download).

`--remove-all-dependencies`, `--purge-all-dependencies`, and `--force-wipe-all-dependencies`
widen the same context-scoped idea to every **project-used** name (still not “everything on
disk”).

=== List-tree: force-wipe (often what you want)

xref:dependencies/managing/force-wiping.adoc[`--force-wipe-dependencies`] names leaves from the
`--list-dependencies` tree — versions, branch stems, Conan package folders, <...> —
**without** requiring those leaves to be project-used under the active context. Referenced /
`in use` state does not block the wipe; the long flag name is the acknowledgement.

Despite the dramatic name, this is the everyday reclaim tool when you are cleaning storage
**outside** a matching project build: old Boost versions, leftover location stems, Conan
package trees left by cuppa integration-test runs, caches from another checkout, and so on.
You list what is on disk, name what to delete, dry-run with `-n`, then drop `-n`. You do
**not** need to reconstruct the `sconstruct` and toolchain / variant flags that originally
produced those trees.

`--force-wipe-unreferenced-dependencies` is a rarer orphan sweep for trees this resolve marks
`unreferenced` — prefer named force-wipe filters when you can see the leaf in the list.

[cols="1,2"]
|===
| Action | Page

| Context-scoped build-product reclaim (downloads stay)
| xref:dependencies/managing/removing.adoc[Removing dependencies]

| Context-scoped remove plus matching downloads (extract stays)
| xref:dependencies/managing/purging.adoc[Purging dependencies]

| Context-scoped whole-extract clear-down (re-fetch next build)
| xref:dependencies/managing/wiping.adoc[Wiping dependencies]

| List-tree reclaim by named leaf (context-agnostic), plus orphan sweeps
| xref:dependencies/managing/force-wiping.adoc[Force-wiping dependencies]
|===

CLI summaries also link here from
xref:cli/inspect-and-maintain.adoc#dependency-storage-actions[Inspect and maintain].

Publisher working copies under the in-force publisher root
(`--publisher-root`, else `<storage-root>/publishers`) are a **separate** reclaim
path: xref:dependencies/publishing/list-publishers.adoc#remove-publishers[`--remove-publishers`]
/ `--remove-all-publishers` (comma-separated folder names; full forest table with
`would rm` / `removed` / `skip` REMARK and muted unaffected rows). There is no
purge or wipe for publishers — see that page for the dry-run sample.

[#which-flag-family]
== Which flag family

[cols="2,2,3,3"]
|===
| Flag | Requires project-used name? | What leaves | Typical intent

| `--remove-dependencies=`pass:[<filter>]
| Yes
| Active context only; downloads stay; source Boost may keep the extract
| Reclaim this project's current build products / selected package tree

| `--remove-all-dependencies`
| Yes (every project-used name)
| Same as remove for each project-used name
| Clear this project's active-context caches in one go

| `--purge-dependencies=`pass:[<filter>]
| Yes
| Remove **plus** matching downloads; extract stays
| Free build products (or package trees) and their download archives

| `--purge-all-dependencies`
| Yes (every project-used name)
| Purge for every project-used name — not every leftover on disk
| Project-wide active-context purge

| `--wipe-dependencies=`pass:[<filter>]
| Yes
| **Whole extract** + matching downloads for the active context
| Clean slate so the next online build re-fetches

| `--force-wipe-all-dependencies`
| Yes (every project-used name)
| Whole extracts + downloads for every project-used name in the active context
| Wide context-scoped clear-down; the `force-` prefix marks the breadth

| `--force-wipe-dependencies=`pass:[<filter>]
| No — any list-tree leaf
| Exact named leaves (versions / branches / stems), including unused siblings under a used identity; matching downloads
| Everyday disk reclaim from the list tree (old versions, Conan leftovers, other-project caches)

| `--force-wipe-unreferenced-dependencies`
| No
| Every tree/download this resolve marks `unreferenced` (orphan sweep)
| Rare blunt cleanup after `--list-scope=unreferenced`
|===

Do not combine remove, purge, and wipe modes in one invocation. Develop working
copies are never deleted. SCons `-n` / `--no-exec` is a dry run for all of these.


[#dependency-filters]
[#dependency-tokens]
== Dependency filters

`--remove-dependencies`, `--purge-dependencies`, `--wipe-dependencies`, and
`--force-wipe-dependencies` share one filter grammar:

[source,text]
----
[selector]name
[selector]name/qualifier
name
name/qualifier
----

* **Selector** (optional) restricts the match to one **dependency type** — the same axis as
  `--list-dependencies` type groups (see xref:#dependency-types-and-selectors[Dependency types and selectors]).
* **Untyped** filters (no `[<...>]` prefix) match across **all** types on purpose (for example a
  source Boost extract and a GitLab package that share the name `boost`).
* **Qualifier** is the leaf shown in the list tree (`1.91.0`, `@11.1.1`). Shell / `fnmatch`
  wildcards (`*`, `?`, `[<...>]`) are accepted on the name and/or qualifier; quote them so the shell
  does not expand them.
* Remove / purge / wipe still require **project-used** names under the **active context**;
  force-wipe does not.
* Reports nest **summary → type → identity → version → leaves**, matching `--list-dependencies`
  on the identity/version axis. A summary root shows **removing** / **wiped** vs **remaining**
  bytes. Version marks follow extract rollups (`✔✔✔` full, `-✔-` partial, `---` untouched).
  Match versions with `name/qualifier` filters (for example `boost/1.8*`), not a glued name like
  `boost*1.8*`.

[#dependency-types-and-selectors]
=== Dependency types and selectors

Order matches the type groups in `--list-dependencies` reports.

[cols="2,3,4"]
|===
| Dependency type (list label) | What it is | Selector aliases (docs prefer the first)

| Repository dependencies
| VCS / location working copies (including develop-shaped trees under the dependencies root)
| `[repository]`, `[repo]`, `[vcs]`, `[vcs_dependency]`, `[repository_dependency]`; quiet alias `[location]`

| GitLab packages
| Registry package extracts under the GitLab generic layout
| `[gitlab]`, `[gl]`, `[gitlab_package]`, `[gitlab-package]`

| Conan packages
| Conan package trees Cuppa tracks under the dependencies root
| `[conan]`, `[cn]`, `[conan_package]`

| Source archives
| Extracted source / archive trees (for example Boost built from a tarball)
| `[source]`, `[sa]`, `[archive]`, `[source_archive]`, `[source-archive]`

| Toolchains
| Fetched / registered compiler installs under the toolchains area
| `[toolchain]`, `[toolchains]`, `[tc]`, `[compiler]`

| Untyped (no selector)
| Match the name (and optional qualifier) in **every** type above
| _(omit the `[<...>]` prefix)_

| Reserved
| Future GitHub generic packages — not implemented; must not be used as GitLab
| `[gh]`, `[github]`, `[github_package]`, `[github-package]`
|===

[source,shell]
----
cuppa -Q -D -n --remove-dependencies='[source]boost'
cuppa -Q -D -n --wipe-dependencies='[gitlab]boost_package/1.91'
cuppa -Q -D -n --force-wipe-dependencies='[source]boost/1.8*'
----
