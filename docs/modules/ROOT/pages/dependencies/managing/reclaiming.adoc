= Reclaiming dependency storage
:description: Overview of remove, purge, wipe, and force-wipe — tokens, flag families, and selection glance table

Choose how aggressively to reclaim trees under `--dependencies-root` (and archives under
`--downloads-root`). This page is the map: flag differences, dependency tokens, a shared
example inventory, and a glance table of common filters.

Detailed semantics and worked examples (why + dry-run reports) live on the action pages:

| Action | Page

| Whole extract clear-down for project-used names (re-fetch next build)
| xref:dependencies/managing/wiping.adoc[Wiping dependencies]

[#which-flag-family]
== Which flag family

[cols="2,2,3,3"]
|===
| Flag | Requires project-used name? | What leaves | Typical intent

| `--remove-dependencies=<tokens>`
| Yes
| Current toolchain / variant / location-match **selection** only; downloads stay; `storage_clean` deps may keep the extract
| Reclaim selected products or the selected package variant

| `--remove-all-dependencies`
| Yes (every project-used name)
| Same as remove for each project-used name
| Clear this project's selected caches in one go

| `--purge-dependencies=<tokens>`
| Yes
| Remove **plus** matching downloads for the same selection
| Free extract products (or trees) and their archives

| `--purge-all-dependencies`
| Yes (every project-used name)
| Purge for every project-used name — not every leftover on disk
| Project-wide selected purge

| `--wipe-dependencies=<tokens>`
| Yes
| **Whole extract** + matching downloads for the selection (Boost `storage_clean` does not stop at products)
| Clear-down so the next online build re-fetches

| `--force-wipe-all-dependencies`
| Yes (every project-used name)
| Whole extracts + downloads for every project-used name in the selection
| Wide clear-down; the `force-` prefix marks the breadth

| `--force-wipe-dependencies=<tokens>`
| No — any list-tree leaf
| Exact named leaves (versions / branches / stems), including unused siblings under a used identity; matching downloads
| Reclaim old Boost versions, unused location stems, leftovers remove cannot name

| `--force-wipe-unreferenced-dependencies`
| No
| Every tree/download this resolve marks `unreferenced` (orphan sweep)
| Rare blunt cleanup after `--list-scope=unreferenced`
|===

Do not combine remove, purge, and wipe modes in one invocation. Develop working
copies are never deleted. SCons `-n` / `--no-exec` is a dry run for all of these.


[#dependency-tokens]
== Dependency tokens

`--remove-dependencies`, `--purge-dependencies`, `--wipe-dependencies`, and
`--force-wipe-dependencies` share one token grammar:

[source,text]
----
[selector]name
[selector]name/qualifier
name
name/qualifier
----

* **Selector** (optional) restricts the match to one **dependency type** — the same axis as
  `--list-dependencies` type groups (see xref:#dependency-types-and-selectors[Dependency types and selectors]).
* **Untyped** tokens (no `[<...>]` prefix) match across **all** types on purpose (for example a
  source Boost extract and a GitLab package that share the name `boost`).
* **Qualifier** is the leaf shown in the list tree (`1.91.0`, `@11.1.1`). Shell / `fnmatch`
  wildcards (`*`, `?`, `[<...>]`) are accepted on the name and/or qualifier; quote them so the shell
  does not expand them.
* Remove / purge / wipe still require **project-used** names; force-wipe does not.
* Reports nest **summary → type → identity → version → leaves**, matching `--list-dependencies`
  on the identity/version axis. A summary root shows **removing** / **wiped** vs **remaining**
  bytes. Version marks follow extract rollups (`✔✔✔` full, `-✔-` partial, `---` untouched).
  Match versions with `name/qualifier` tokens (for example `boost/1.8*`), not a glued name like
  `boost*1.8*`.

[#dependency-types-and-selectors]
=== Dependency types and selectors

[cols="2,3,4"]
|===
| Dependency type | What it is | Selector aliases (docs prefer the first)

| Source archives
| Extracted source / archive trees (for example Boost built from a tarball)
| `[source]`, `[sa]`, `[archive]`, `[source_archive]`, `[source-archive]`

| GitLab packages
| Registry package extracts under the GitLab generic layout
| `[gitlab]`, `[gl]`, `[gitlab_package]`, `[gitlab-package]`

| Repositories
| VCS / location working copies (including develop-shaped trees under the dependencies root)
| `[repository]`, `[repo]`, `[vcs]`, `[vcs_dependency]`, `[repository_dependency]`; quiet alias `[location]`

| Conan
| Conan package trees Cuppa tracks under the dependencies root
| `[conan]`, `[cn]`, `[conan_package]`

| Toolchains
| Fetched / registered compiler installs under the toolchains area
| `[toolchain]`, `[toolchains]`, `[tc]`, `[compiler]`

| Untyped (no selector)
| Match the name (and optional qualifier) in **every** type above
| _(omit the `[<...>]` prefix)_

| Reserved
| Future GitHub generic packages — not implemented; must not be used as GitLab
| `[gh]`, `[github]`, `[github_package]`, `[github-package]`
|===

[source,shell]
----
cuppa -Q -D -n --remove-dependencies='[source]boost'
cuppa -Q -D -n --wipe-dependencies='[gitlab]boost_package/1.91'
cuppa -Q -D -n --force-wipe-dependencies='[source]boost/1.8*'
----
