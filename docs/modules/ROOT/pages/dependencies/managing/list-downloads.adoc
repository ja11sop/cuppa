[#list-downloads]
== Listing downloads

`--list-downloads` walks the downloads root and prints a hierarchical table of cached archives
together with the dependency trees they regenerate. Before the walk it prints
`Collating downloads tree...` (text and verbose only). Rows are grouped **used** first then
**unused** by default (same Option A scopes as `--list-dependencies`), then by type, then by
identity. Under each identity the archive leaf is the file
under `--downloads-root`; an `[E]` child shows the matching tree under
`--dependencies-root` (GitLab toolchain folder, or `name/version` for HTTP source archives).
Parent `SIZE` values roll up **archive** bytes only so the footer answers how much download
cache would be reclaimed. Extract sizes stay on the `[E]` leaf for impact.

`--list-scope` filters the same way as
xref:dependencies/managing/list-dependencies.adoc[`--list-dependencies`]
(`all` / `resolve` / `referenced` / `compact` / `unreferenced`). `--list-format=verbose` adds LOCATION
(archive path and extract path). `--list-format=json` includes `tree`, flat `entries` with
`kind` `archive` or `product`, `archive_count`, `scope`, and archive-only `total_bytes` /
`unreferenced_bytes`. See
xref:integration/test-list-downloads.adoc[`test_list_downloads`].

[source,shell]
----
cuppa -Q -D --list-downloads
cuppa -Q -D --list-downloads --list-scope=resolve
cuppa -Q -D --list-downloads --list-scope=referenced
cuppa -Q -D --list-downloads --list-scope=compact
cuppa -Q -D --list-downloads --list-format=verbose
cuppa -Q -D --list-downloads --list-format=json
----

Type groups follow the same order as `--list-dependencies` (gitlab packages before source
archives). Under each type row a hanging `│` connects to the first identity.

[cols="1,4"]
|===
| Scope | Effect

| `all` (default)
| Usage grouping: used downloads, then unused downloads

| `resolve`
| Resolve-identity grouping: referenced from downloads, then unreferenced downloads
  (unused sibling archives stay under referenced identities)

| `referenced`
| Resolve-identity filter: identities with at least one resolve-bound archive/product
  (**including unused sibling archives**). Footer: `N archives, X download total, X referenced`

| `compact`
| Used-only: resolve-bound archives/products — no unused siblings. Footer:
  `N archives, X download total, X compact`

| `unreferenced`
| Orphan identities only (no resolve-bound leaf) — not unused siblings of tips
|===

Choose `referenced` or `all`/`resolve` when you want to see stale siblings you might
force-wipe by name, and `compact` for a short “what this selection uses” view.
