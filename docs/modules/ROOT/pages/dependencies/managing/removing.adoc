= Removing dependencies
:description: --remove-dependencies and --remove-all-dependencies — context-scoped reclaim

For the flag map, tokens, shared inventory, and glance table, see
xref:dependencies/managing/reclaiming.adoc[Reclaiming storage].
Remove is the first step on the
xref:dependencies/managing/reclaiming.adoc#two-reclaim-paths[context-scoped ladder]
(remove → purge → wipe). For naming leaves from the list tree without matching this
project's active context, use
xref:dependencies/managing/force-wiping.adoc[force-wipe] instead.

[#remove-dependencies]
== Removing dependency trees

`--remove-dependencies=name1,name2` and `--remove-all-dependencies` delete trees under the
dependencies root for the named registry dependencies (or every default dependency), scoped to
the **active context** — the current toolchain / variant / location-match flags (the same
options that decide where cuppa writes). They exit without building. Downloads, develop working
copies, and unreferenced trees that are not named stay put; siblings for other toolchains or
branches are reported as left behind. SCons `-n` is a dry run.

Names are the keys this project uses: `auto_enable_dependencies` (legacy:
`default_dependencies`) plus names imported via `import_dependencies` (legacy:
`dependencies=[<...>]`). Built-in factories that module scan always registers
(`boost`, `qt4`, `<...>`) are **not** removable unless the project names them that way (for example
in `auto_enable_dependencies`). On-disk folder names and listing short names are rejected. An
unknown or unused name prints an error (rejected name error-coloured and emphasised) and a
ruled tree of dependencies that *can* be removed for the active context (the in-use /
referenced picture from `--list-dependencies`, without unreferenced leftovers), after
`Collating dependency tree...`. See
xref:integration/test-remove-dependencies.adoc[`test_remove_dependencies`].

Tokens may also use the shared `[selector]name[/qualifier]` form described in
xref:dependencies/managing/reclaiming.adoc#dependency-tokens[Dependency tokens] — for example `[source]boost` or
`[gitlab]boost_package/1.91` — to restrict by dependency type and optional leaf qualifier.
The glance table of common filters is on
xref:dependencies/managing/reclaiming.adoc#filter-examples[Reclaiming storage];
remove-specific walkthroughs are in xref:#worked-remove-examples[Worked examples] below.

Source Boost (the `boost` dependency that builds with b2) stores headers and all toolchain
variant products inside one extract folder. When that dependency implements context-scoped
`storage_clean` (Boost does), `--remove-dependencies=boost` deletes only the b2 **stage** and
matching Boost.Build toolset directories under `--build-dir` (`bin.<abi>`) for the current
toolchain / variant / arch flags — not the whole `bin.<abi>` tree.

The extract root, headers, and the `b2` binary stay so a later build does not need to
re-download the tarball. Other stage trees and other toolsets' intermediates under the same
extract are reported as left behind.

Removal leaves use honest scopes: cuppa-precise for stage
(`clean/build.c{plus}{plus}2c [clang211/debug/x86_64]`) and Boost.Build toolset **family** for bin
(`clean/bin.c{plus}{plus}2c [clang-linux-21*/debug]` — major family ± patch dirs such as
`clang-linux-21.1`, not a cuppa minor like `clang211`). The identity SIZE is the full extract
(same basis as `--list-dependencies`). Products and a muted `source assets` leaf hang under an
`[E]` extract row (`---` nothing going, `-✔-` partial, `✔✔✔` everything under it going). Empty
`bin.<abi>` husks with no toolset children stay on disk but are omitted from the table. The
freed-space summary reports the remaining archive size after product removal.

`--boost-patched` selects the `patched/` home; without it, `clean/` is active and `patched/`
products show as leftovers. After a live product clean, cuppa refreshes that extract's inventory
with an exact size; verify with `cuppa -Q -D --list-dependencies`.

Dependencies without `storage_clean` still remove their whole owned tree under the dependencies
root (for example GitLab `boost_package` removes the selected package variant folder). Authors
declare those trees with `storage_paths()` and optional `storage_clean()` — see
xref:dependencies/authoring/extending.adoc[Writing your own dependencies].

[source,shell]
----
cuppa -Q -D --remove-dependencies=boost_package
cuppa -Q -D --dbg --toolchains=gcc --remove-dependencies=boost_package
cuppa -Q -D --dbg --remove-dependencies=boost
cuppa -Q -D --dbg --remove-dependencies='[source]boost'
cuppa -Q -D -n --remove-dependencies=widget
cuppa -Q -D --remove-all-dependencies
----

The identity row rolls up size (muted) and emphasises the dependency name and package version.
Selected leaves use a check (or ballot on failure) with the removal-notice colour; leftover
leaves stay muted with a `-` mark. Tree stems are subdued. `LAST USED` comes from inventory
resolve stamps when present, otherwise the tree's modification time. Passing multiple
toolchains (for example `--toolchains=gcc,clang`) removes each matching package variant.

With `--develop`, a develop working copy is never deleted; the report lists it under skipped
develop paths. Cached stems under the dependencies root may still be removed when selected.



[#from-list-to-remove]
== From list to remove

Most reclaim work starts from the listing, not from memory of folder names. Treat
xref:dependencies/managing/list-dependencies.adoc[`--list-dependencies`] as the source of truth
for identity labels, versions, and which leaves are `in use`.

. List the trees this project cares about:

[source,shell]
----
cuppa -Q -D --list-dependencies
cuppa -Q -D --list-dependencies --list-scope=unreferenced
----

. Read the hierarchy: type group → identity (registry name or short name) → version / branch →
  toolchain or extract leaves. For GitLab packages the **identity** is the registry name
  (for example `boost_package`); the on-disk package folder may differ (for example `boost/<version>`).
  Listing short names are **not** remove tokens unless they are also project-used names.

. Map labels to tokens (see
  xref:dependencies/managing/reclaiming.adoc#dependency-tokens[Dependency tokens]):

* Untyped project-used name: `boost_package` or `boost` — remove / purge / wipe for the active context.
* Typed dependency type: `[gitlab]boost_package` or `[source]boost` (see
  xref:dependencies/managing/reclaiming.adoc#dependency-types-and-selectors[Dependency types and selectors]).
* Version / leaf qualifier: `[gitlab]boost_package/1.91` or `boost/1.8*` (quote wildcards).
* Unqualified VCS duplicate shown as `@master (unqualified)`: force-wipe with `name/@`.

. Dry-run first (`-n`), then drop `-n`. Prefer the
  xref:dependencies/managing/reclaiming.adoc#filter-examples[filter examples] table when choosing the flag family:

[source,shell]
----
cuppa -Q -D -n --remove-dependencies='[gitlab]boost_package'
cuppa -Q -D -n --wipe-dependencies='[gitlab]boost_package/1.91'
cuppa -Q -D -n --force-wipe-dependencies='[source]boost/1.8*'
----

Expected report shapes match the HTML samples later on this page
(`remove-gitlab-dry-run`, `remove-boost-product-clean`, and the wipe / purge samples).

. Choosing a flag family

* Use **remove** / **purge** / **wipe** when you are reclaiming *this* project's caches under
  the **active context** (matching toolchain / variant flags).
* Use **force-wipe** when you are naming leaves from `--list-dependencies` — old versions,
  Conan leftovers, caches from another checkout or test run — without reconstructing that
  context. See xref:dependencies/managing/reclaiming.adoc#two-reclaim-paths[Two reclaim paths].
* List leftovers with `--list-scope=unreferenced` (and
  xref:dependencies/managing/list-downloads.adoc[`--list-downloads`]) before an orphan wipe.
* Do not use a **listing short name** or on-disk folder when the project key is different
  (remove prints an error and a ruled tree of names that *can* be removed).

[#ex-remove-used-source]
=== Remove used variants for a source-archive dependency (active context)

`--remove-dependencies='[source]boost'` (or untyped `boost` when only the source type is
in play) cleans **used** context outputs for that source-archive dependency — for Boost,
the b2 stage / toolset dirs under the **used** version for the **active context** — and
leaves the extract (`storage_clean`). It does **not** wipe unused version leaves. That
requires `boost` to be a **project-used** name.
