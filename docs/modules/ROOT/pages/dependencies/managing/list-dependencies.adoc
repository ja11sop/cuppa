= Listing dependency trees
:description: --list-dependencies — how to read the tree, scopes, formats, and package requires

[#list-dependencies]
== Listing dependency trees

`--list-dependencies` shows what Cuppa has under the dependencies root for this project:
which trees are in use for the current resolve, which are leftovers, how large they are, and
how they nest.

It exits without building (exit 0 even when some expected trees are missing). Before the walk
it prints `Collating dependency tree...` (text and verbose only; omitted for JSON).

[source,shell]
----
cuppa -Q -D --list-dependencies
cuppa -Q -D --list-dependencies --list-scope=resolve
cuppa -Q -D --list-dependencies --list-scope=referenced
cuppa -Q -D --list-dependencies --list-scope=compact
cuppa -Q -D --list-dependencies --list-format=verbose
cuppa -Q -D --list-dependencies --list-format=json
cuppa -Q -D --list-dependencies --exact-sizes
----

For a consume-only story (nested packages without publishing), see
xref:dependencies/using/building-with-packages.adoc[Building with package dependencies].
When you are ready to reclaim disk, map labels from this tree to remove / wipe filters — see
xref:dependencies/managing/removing.adoc#from-list-to-remove[From list to remove].

== How to read the listing

Columns are **SIZE**, **LAST USED**, **REMARK**, and **DEPENDENCY**.

* **SIZE** — tree size (right-aligned). Missing or sampled inventory sizes are upgraded to
  exact on listing (the first run on a large root can take a while; later runs reuse the
  cache). Pass `--exact-sizes` to force a full remeasure.
* **LAST USED** — from inventory resolve stamps when present, otherwise the tree's
  modification time.
* **REMARK** — `in use` / `N used` when more than one leaf is selected /
  `not extracted` / `missing` / `develop`, and similar roll-up notes.
* **DEPENDENCY** — the hierarchy: section → type → identity → version or branch → leaf.

=== Sections and types

By default (`--list-scope=all`) the report opens with **used** (selected for this resolve),
then **unused** (present on disk but not selected). Under each section, trees group by
**dependency type**:

Type groups always appear in this order (empty groups are omitted):

* **repository dependencies** — location / VCS working copies (branches and stems such as `@master`)
* **gitlab packages** — registry package extracts (versions → toolchain leaves)
* **conan packages** — Conan trees Cuppa tracks under the dependencies root (when present)
* **source archives** — extracted archives such as source Boost (versions → build products)
* **toolchains** — fetched compiler installs under the toolchains area (when listed here)

Default dependencies that are expected but absent on disk appear as a **gap** remark.
When Cuppa can point at a registry URL and/or a cached download archive, the remark is
`not extracted` (same info paint as `in use`; SIZE shows `??` until extract size is
known) — the next **online tip build** retrieves them. Bare `missing` is reserved for
gaps with no retrieve story. The used section opens with roll-ups when useful:
`dependencies in use`, then
`not extracted dependency` / `not extracted dependencies` (or hard `missing`), then
`potentially stale dependencies` for other non-selected bound leaves (for example
develop-shadowed stems).

[#list-dependencies-missing]
=== Gap remarks: not extracted vs missing

Listing is **inventory** (still exit 0). A gap row does **not** mean “absent from the
registry” or “you must cascade.”

[cols="2,3,3"]
|===
| Signal
| Means
| Does **not** mean

| `not extracted` (used GitLab / package row with registry URL or `[dl]`)
| No tip extract for that identity under the dependencies/downloads roots yet
| Package absent from GitLab; cascade required

| `missing` (no known registry URL / archive)
| Tip expects a tree Cuppa cannot point a retrieve path at
| Automatically solvable by `--cascade` / `--clone-publishers`

| Unused sibling stem (e.g. `gcc15_...` present while tip wants `gcc16_...`)
| Another toolchain extract exists; tip wants a different stem
| Package never published
|===

**Consume first:** edit pins, run an online tip configure/build
(`cuppa ...` or SCons `-n` for configure-only — `-n` is not a cascade plan), then
re-list. Only reach for
xref:dependencies/publishing/cascade.adoc[cascade] when the goal is nest-publish /
nest-build **publisher trees**, not tip consume cache.

IMPORTANT: Do **not** treat `not extracted` as a cue to pass `--cascade` or
`--clone-publishers`. Those place publisher working trees; tip retrieve downloads
registry archives into the tip toolchain stem.

On-disk paths are omitted by default. Pass `--list-format=verbose` for a LOCATION column, or
`--list-format=json` for a machine-readable tree. With a non-`storage`
`--list-location`, compact text still stays column-free: the identity DEPENDENCY label
shows a plain `[dev]` / `[pub]` mark and a subdued working-copy path in place of (or
after) the usual bracket detail — see
xref:#working-copy-location-list-location[Working-copy location].

NOTE: GitLab packages with traveling manifests also nest a ``requires`` group under tip
versions. That is covered in xref:#list-dependencies-requires[Package ``requires`` graphs]
after the general shape below — it is one package feature, not the whole listing story.

== Choosing a scope

`--list-scope` selects which part of the listing to show. Leaf bind (`referenced` /
`missing` / `cached` vs `unreferenced`) is unchanged; scope chooses **report grouping** and
which rows appear:

* `all` (default) — **usage** grouping: `used` then `unused`. Unused versions / toolchains
  of tip identities sit under **unused**.
* `resolve` — **resolve-identity** grouping: `referenced` then `unreferenced`. Unused
  siblings stay under the same referenced identity.
* `referenced` — resolve-identity filter: identities with at least one resolve-bound leaf
  (siblings included); referenced section only.
* `unreferenced` — resolve-identity filter: identities with no resolve-bound leaf (orphan
  leftovers only — not unused siblings of tips).
* `compact` — **used-only**: resolve-bound leaves (`in use` / gap remarks / develop-shadowed);
  used section only.

`compact` is the short used-only view; it is not the same as `referenced`.
You can still combine any scope with `verbose` or `json`. Persist a preference in
`~/.cuppaconfig` or `configure.conf` as `list_scope = 'resolve'` or
`list_scope = 'compact'`.
`--list-dependencies-scope` remains as a deprecated alias.

[#list-dependencies-requires]
== Package ``requires`` graphs

GitLab packages that ship ``cuppa-publish.json`` (or a legacy ``cuppa-dependency.json``)
show a ``requires`` group under each tip version: the on-disk **package closure** as sized
identity trees (versions → toolchains). Nested packages keep label-style ``requires`` edges
(name, version, optional ``libs: <...>``).

Closure-only packages leave the top-level unused / unreferenced lists and are protected from
``--force-wipe-unreferenced-dependencies``. See
xref:dependencies/using/gitlab.adoc#transitive-package-dependencies[Transitive package dependencies].

The same usage split that applies to tip identities also applies inside tip ``requires``
forests under ``--list-scope=all``: only tip-matching / closure-in-use nest toolchains hang
under used → requires; leftover nest variants appear as top-level unused gitlab identities.
``--list-scope=resolve`` keeps those leftovers under the tip requires group instead.

``beta`` toolchain (``gcc16``) so the scopes diverge.

== Verbose LOCATION and ``[dl]`` / ``[dev]`` / ``[pub]``

Under `--list-format=verbose` a LOCATION column is added. What it shows depends on the type:

* *Repositories (location dependencies)* — bare repository URL on the identity; `URL@branch`
  on each branch leaf.
* *GitLab packages* — empty on the identity; registry `<...>/package/version` on the version
  row; archive basename on each toolchain leaf.
* *Source archives* (Boost source tarballs, GitHub release zips, and similar) — short name
  such as `boost` or `github.com/fmtlib/fmt` on the identity; version or tag on each child;
  download URL on the version leaf.

When a regenerating archive exists under the downloads root (`--downloads-root`, for example
`~/.cuppa/downloads` or a legacy `~/_cuppa/_cache`), LOCATION is prefixed with `[dl]` on the
leaf that names that archive (HTTP/Boost extract rows, and GitLab toolchain archive
basenames — not the GitLab registry URL on the version row). A footer explains the mark in
verbose mode whenever such archives are present. If re-extracting a dependency fails, remove
the corrupt archive under downloads; deleting only the dependency tree is not enough.

[#working-copy-location-list-location]
=== Working-copy location (``--list-location``)

`--list-location` is orthogonal to `--list-format` and `--list-scope`. It overlays
working-copy paths on `--list-dependencies` when a matching develop or publisher tree
exists. Health of those trees stays on
xref:dependencies/managing/develop.adoc[`--list-develop`] and
xref:dependencies/publishing/list-publishers.adoc[`--list-publishers`].

* *Compact text* (default `--list-format=text`) — no LOCATION column. On each identity
  that has a matching working copy (including nested ``requires`` package identities),
  the DEPENDENCY label becomes `name [dev]|[pub] <path>`: the mark and path **replace**
  the usual bracket detail (for example the git host path on a repository identity), or
  **append** after a bare name (for example `boost_package [pub] ~/.cuppa/publishers/boost`).
  The mark is plain and the path is subdued so the identity name stays the focus.
* *Verbose* — LOCATION column shows the same mark and path; DEPENDENCY keeps the
  registry / host detail. Marks stay info-coloured; used `[pub]` / `[dl]` paths are
  info; used `[dev]` paths stay plain.

A footer explains `[dev]` / `[pub]` whenever either mark was painted (compact or verbose).

[cols="2,8"]
|===
| Value | Overlay shows

| `storage` (default)
| No working-copy overlay (verbose LOCATION stays registry / URL / extract as above)

| `publishers`
| Forest path under the in-force publisher root (`--publisher-root`, else
  `<storage-root>/publishers`), prefixed with `[pub]`, when a matching tree exists

| `develop`
| Configured `develop=` path, prefixed with `[dev]`, when configured (does not require
  `--develop`)

| `active`
| What this tip would prefer with the current flags: `[dev]` when `--develop` is on and a
  develop path applies; otherwise `[pub]` when a forest tree matches; otherwise storage.
  Matches cascade `resolve_publisher_dir` precedence
|===

[source,shell]
----
cuppa -Q -D --list-dependencies --list-location=develop
cuppa -Q -D --list-dependencies --list-location=publishers
cuppa -Q -D --list-dependencies --list-format=verbose --list-location=publishers
cuppa -Q -D --list-dependencies --list-format=verbose --list-location=active --develop
----

== Inventory

The inventory under `<dependencies_root>/.cuppa-inventory/` records sizes (exact after
listing upgrades missing or sampled entries; resolve/build may still write samples until
listing upgrades them), optional `remote_location` / `source_url`, and paths of known
download archives so later listings can show LOCATION and `[dl]` without re-guessing.

Listing does not stamp `last_used` or `used_by`; a real `BuildWith` / default-dependency
resolve does, recording the current sconstruct directory in `used_by`. Unqualified VCS stems
that share a default-branch family with `stem@<branch>` are labelled
`@<default> (unqualified)`.
