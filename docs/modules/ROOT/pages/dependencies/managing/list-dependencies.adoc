= Listing dependency trees
:description: --list-dependencies scopes, formats, inventory, and GitLab requires edges

[#list-dependencies]
== Listing dependency trees

`--list-dependencies` walks the dependencies root and prints a hierarchical table: size,
last used, remark (`in use` / `N used` when more than one leaf is selected / `missing` /
`develop`), and dependency identity. Before the walk it prints `Collating dependency tree...`
(text and verbose only; omitted for JSON). When inventory sizes are missing or only sampled
estimates, it prints a short notice and upgrades those trees to exact sizes (the first run on a
large root can take a while; later runs reuse the cache). Pass `--exact-sizes` to force a full
remeasure of every tree. Rows are grouped **used** first then **unused** by default
(usage grouping), then by type (repository dependencies, gitlab packages, source
archives, <...>), then by short name or
registry name, with branch or version children underneath. For tip-selected GitLab package
extracts that contain ``cuppa-publish.json`` (or a legacy ``cuppa-dependency.json``), a
``requires`` group nests the on-disk **package closure** as sized identity trees (versions →
toolchains). Nested packages keep label-style ``requires`` edges (name, version, optional
``libs: <...>``). Closure-only packages leave the top-level unused / unreferenced lists and are
protected from
``--force-wipe-unreferenced-dependencies``. See
xref:dependencies/using/gitlab.adoc#transitive-package-dependencies[Transitive package dependencies].
On-disk paths are omitted by
default; pass `--list-format=verbose` to add a LOCATION column, or `--list-format=json` for a
machine-readable tree (plus flat `entries`, including a ``requires`` array on GitLab leaves).
Default dependencies that are expected but absent appear as `missing`. The used / referenced
section
roll-ups separate `dependencies in use`, `missing dependencies` (when any expected trees are
absent), and only then `potentially stale dependencies` for other non-selected bound
leaves (for example develop-shadowed stems). Unused on-disk siblings of tip identities appear
under the **unused** section by default (use ``--list-scope=resolve`` to keep them under the
same **referenced** identity). The same usage split applies inside tip GitLab ``requires``
forests: only tip-matching / closure-in-use nest toolchains hang under used → requires;
leftover nest variants appear as top-level unused gitlab identities.
It exits without building (exit 0 even when some rows are missing). See
xref:integration/test-list-dependencies.adoc[`test_list_dependencies`] for the integration
scenario.

For the tip-consumer story (nested packages without publishing), see
xref:dependencies/using/building-with-packages.adoc[Building with package dependencies].

[source,shell]
----
cuppa -Q -D --list-dependencies
cuppa -Q -D --list-dependencies --list-scope=resolve
cuppa -Q -D --list-dependencies --list-scope=referenced
cuppa -Q -D --list-dependencies --list-scope=compact
cuppa -Q -D --list-dependencies --list-format=verbose
cuppa -Q -D --list-dependencies --list-format=json
cuppa -Q -D --list-dependencies --exact-sizes
----

`--list-scope` selects which part of the listing to show. Leaf bind
(`referenced` / `missing` / `cached` vs `unreferenced`) is unchanged; scope chooses
**report grouping** and which rows appear:

* `all` (default) — **usage** grouping: `used` then `unused`. Unused versions /
  toolchains of tip identities sit under **unused**.
* `resolve` — **resolve-identity** grouping: `referenced` then `unreferenced`.
  Unused siblings stay under the same referenced identity (Pass A shape).
* `referenced` — resolve-identity filter: identities with at least one
  resolve-bound leaf (siblings included); referenced section only.
* `unreferenced` — resolve-identity filter: identities with no resolve-bound leaf
  (orphan leftovers only — not unused siblings of tips).
* `compact` — **used-only**: resolve-bound leaves (`in use` / `missing` /
  develop-shadowed); used section only.

`compact` is the short used-only view; it is not the same as `referenced`.
You can still combine any scope with `verbose` or `json`. Persist a preference in
`~/.cuppaconfig` or `configure.conf` as `list_scope = 'resolve'` or
`list_scope = 'compact'`.
`--list-dependencies-scope` remains as a deprecated alias.

== Verbose LOCATION and ``[D]``

Under `--list-format=verbose` a LOCATION column is added. What it shows depends on the type:

* *Location dependencies* — bare repository URL on the identity; `URL@branch` on each branch leaf.
* *GitLab packages* — empty on the identity; registry `<...>/package/version` on the version row;
  archive basename on each toolchain leaf.
* *Source archives* (Boost source tarballs, GitHub release zips, and similar) — short name such as
  `boost` or `github.com/fmtlib/fmt` on the identity; version or tag on each child; download URL
  on the version leaf.

When a regenerating archive exists under the downloads root (`--downloads-root`, for example
`~/.cuppa/downloads` or a legacy `~/_cuppa/_cache`), LOCATION is prefixed with `[D]` on the
leaf that names that archive (HTTP/Boost extract rows, and GitLab toolchain archive basenames —
not the GitLab registry URL on the version row). A footer explains the mark in verbose mode
whenever such archives are present. If re-extracting a dependency fails, remove the corrupt
archive under downloads; deleting only the dependency tree is not enough.

== Inventory

The inventory under `<dependencies_root>/.cuppa-inventory/` records sizes (exact after listing
upgrades missing or sampled entries; resolve/build may still write samples until listing
upgrades them), optional
`remote_location` / `source_url` (configured or reconstructed remotes), and paths of known
download archives so later listings can show LOCATION and `[D]` without re-guessing. Listing
does not stamp `last_used` or `used_by`; a real `BuildWith` / default-dependency resolve does,
recording the current sconstruct directory in `used_by`. Unqualified VCS stems that share a
default-branch family with `stem@<branch>` are labelled `@<default> (unqualified)`.
