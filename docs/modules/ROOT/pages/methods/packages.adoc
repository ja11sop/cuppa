= Package methods
:description: PublishPackage and InstallPackage

Cuppa package methods stage and publish libraries for registry or Conan consumers.
Publisher trees often combine `CMakeConfigure` / `CMakeBuild` / `CMakeInstall` (or
raw `Command()`), `Install()`, and `Depends()` / `Requires()` — see
xref:dependencies/publishing/amend-and-external.adoc#publishing-from-external-cmake[Publishing from an external CMake build],
xref:methods/staging-files.adoc[Staging files], and xref:methods/depends.adoc[Depends].

== Behaviour summary

[cols="1,3",options="header"]
|===
| Axis | Detail

| Returns | Package-related nodes
| Evaluation | Configure / build; upload typically requires `--publish-package`; metadata-only retar uses `--amend-package-manifest` (skips acquire/CMake)
| Output paths | Package layout under cuppa package roots / registry archives
| Progress | As wired by package publishers / CMake methods
|===

== Methods

[cols="2,3"]
|===
| Method | Role

| `env.DownloadExtract(<...>)`
| Download a URL archive into the variant tree, extract, stamp a marker (default `CMakeLists.txt`)

| `env.RemoveEmptyDirs(<...>)`
| Remove empty submodule placeholder dirs after archive extract (stamped); `gitmodules=True` or all empty children; `names=` overrides

| `env.CMakeConfigure(<...>)`
| Configure an external CMake project (toolchain/variant flags via `cuppa.buildsys.cmake`)

| `env.CMakeBuild(<...>)`
| `cmake --build`; Cuppa `--parallel` → `--parallel N`, otherwise `--parallel 1` (pass `jobs=False` to omit)

| `env.CMakeInstall(<...>)`
| `cmake --build <...> --target install` (default omits `--parallel`)

| `env.PublishPackage(<...>)`
| Build (and optionally publish) a package; GitLab generic tarball or Conan `export-pkg` via a publisher object; upload requires `--publish-package`; GitLab metadata-only retar with `--amend-package-manifest` (see xref:dependencies/publishing/amend-and-external.adoc#amend-package-manifest[Amending metadata without rebuilding])

| `env.InstallPackage(<...>)`
| Install a package locally and extend `SYSINCPATH`
|===

Minimal GitLab-oriented sketch (full publishers and Conan on the packages hub):

[source,python]
----
Import('env')
from cuppa.package_managers.gitlab import GitlabPackagePublisher

lib = env.BuildStaticLib('widget', ['widget.cpp'])
publisher = GitlabPackagePublisher(
    env,
    source_include_dir='include',
    source_lib_dir=env['abs_final_dir'],
    registry='https://gitlab.example.com/api/v4/projects/org%2Fregistry',
    package='widget',
    version='1.0.0',
)
env.PublishPackage(lib, publisher=publisher)
----

Run a release build with upload when you intend to push:

[source,sh]
----
cuppa -D --rel --publish-package
----

See xref:dependencies/publishing/packages.adoc[Publishing packages] for `GitlabPackagePublisher` and `ConanPackagePublisher` usage,
including xref:dependencies/publishing/gitlab.adoc#publish-version-latest[floating ``version="latest"``]
(seed may stay floating; staged archive and upload stay concrete).

Custom `Command()` steps that wrap external CMake generate/build before `Install()` are common in
publisher sconscripts — see xref:methods/custom-commands.adoc[Custom commands] and
xref:dependencies/publishing/amend-and-external.adoc#publishing-from-external-cmake[Publishing from an external CMake build].
