= Coverage methods
:description: Coverage collation helpers

Cuppa's coverage methods collect per-test and union reports under `_artefacts/coverage/`
(legacy `_artifacts/` is still honoured when present).
They are usually called from the same test sconscript that runs `BuildTest()` — see
xref:methods/test-run.adoc[Test and run] for the everyday pattern.

== Behaviour summary

[cols="1,3",options="header"]
|===
| Axis | Detail

| Returns | Report / collation nodes
| Evaluation | Build / post-build (active with `--cov` and related actions)
| Output paths | Under `_artefacts/coverage/` (toolchain-scoped HTML and JSON)
| Progress | Collation participates where wired through `NotifyProgress`
|===

== Methods

[cols="2,3"]
|===
| Method | Role

| `env.Coverage(program, sources, <...>)`
| Run coverage tooling for a binary (active with `--cov` / related actions)

| `env.CollateCoverageFiles(sources, destination=<...>)`
| Collate one test's HTML and JSON into a directory named after that test. The directory belongs to that collation target and is removed by `-c`

| `env.CollateCoverageIndex(<...>)`
| Master coverage index across tests (and, in the site layout, toolchains)
|===

[IMPORTANT]
====
`--cov` and `--test` are separate on purpose.

* `--cov` selects the coverage *variant* (instrumented compile/link). It does **not** run tests.
* `--test` runs test actions and lets coverage collection / collation run after those binaries execute.

`--cov --test --parallel` is supported. Each test writes its `.gcda` under `gcov-data/{program}`, and that program's HTML and JSON are produced on their own. `BuildTest` still runs coverage after that test finishes.

For a small tree where you do not need `--parallel`, a single command is fine:

[source,sh]
----
cuppa -D --cov --test --toolchains=gcc
----
====

[NOTE]
====
`--parallel` runs tests at the same time. A test that shares a port, a database, or another fixture with another test is not safe under `--parallel`, with or without `--cov`. That is the sconscript's concern.
====

Coverage instrumentation is supported for GCC and Clang; MSVC does not participate.

Object files for instrumented sources live under the mirrored `working/` tree (same layout as
`Compile()`). The `.gcno` notes stay beside those objects. When coverage is active the test
writes `.gcda` under `gcov-data/{program}`, and `gcov` reads it there. Nested same-basename
sources stay distinct under `--cov` as well.

After `BuildTest()`, projects commonly append:

[source,python]
----
coverage_files.append(env.CollateCoverageFiles(test, destination=coverage_dir))
# <...>
env.CollateCoverageIndex(coverage_files, destination=coverage_dir)
----

See xref:testing-coverage.adoc[Testing and coverage] for report layout and analysis tips.
HTML test reports (`GenerateHtmlTestReport()` / `CollateTestReportIndex()`) are separate plugins that
often run in the same sconscript — see xref:methods/test-reporting.adoc[Test reporting].
