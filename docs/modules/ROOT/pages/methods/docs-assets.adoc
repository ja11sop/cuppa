= Documentation and asset methods
:description: AsciiDoc, Markdown, SCSS, version headers, and redirect capture

Builders that turn documentation and assets into variant outputs under `final/` (or related
trees). `CreateVersion` for C++ version sources is also summarised on
xref:methods/files-and-templates.adoc[Files and templates].

== Behaviour summary

[cols="1,3"]
|===
| Returns | Build nodes for generated artefacts
| Evaluation | Build action
| Output paths | Several emitters still use flat `\{final}/\{basename}` — nested same-basename sources can collide (https://github.com/ja11sop/cuppa/issues/233[#233]). `CreateVersion` uses offset paths under `working/`. `RenderJinjaTemplate` often mirrors path offsets under `final/`.
| Progress | Yes where emitters create action nodes
|===

== Methods

[cols="2,3"]
|===
| Method | Role

| `env.ExpandTemplateFile` / `env.RenderJinjaTemplate`
| Template expansion

| `env.MarkdownToHtml` / `env.AsciidocToHtml`
| Doc conversion builders

| `env.CompileScss`
| SCSS → CSS

| `env.RunAndRedirectToFile`
| Capture subprocess stdout to a file

| `env.CreateVersion(…)`
| SCM-aware generated version sources (often beside `Build`)
|===

Until https://github.com/ja11sop/cuppa/issues/233[#233] lands, avoid feeding two
`readme.md` files from different directories into `MarkdownToHtml` without explicit distinct
targets — they can collide on `\{final}/readme.html`.
