= Install methods
:description: Install and InstallAs for staging files under final/ and package layouts

`Install` and `InstallAs` copy files into a destination directory as build actions.
In Cuppa projects they show up most often when *publishing* a package (headers and libraries into
a package tree) or when staging a handful of assets under `final/`. Everyday test and service
artefact copies usually use Cuppa's xref:methods/files-and-templates.adoc[`CopyFiles`] instead —
pick the tool that matches the job, not the provenance of the call.

Upstream reference (optional, unversioned):
https://scons.org/doc/production/HTML/scons-user/apd.html[SCons user guide — Functions and Environment Methods].

== Behaviour summary

[cols="1,3"]
|===
| Returns | Install nodes
| Evaluation | Build action
| Output paths | Caller-chosen destination; often a package `include/` / `lib/` tree or `env['final_dir']`
| Progress | When a Cuppa method that owns the targets wires `NotifyProgress`; bare `Install` alone does not add Cuppa progress
|===

== `CopyFiles` versus `Install`

[cols="1,3"]
|===
| Call | Prefer when

| `CopyFiles` / `CopyFilesAs`
| Copying build outputs, logs, configs, or docker payloads inside a Cuppa variant layout
  (`final/`, `#_artifacts/…`). Works naturally with `Filter` on test outputs.

| `Install` / `InstallAs`
| Staging into a *package* directory for `PublishPackage`, or installing named assets where you
  want classic Install semantics (including repository-aware installs).
|===

Both create real build edges. For “copy the binary into docker only after it links”, wrap the copy
with xref:methods/depends.adoc[`Requires`] regardless of which copy helper you chose.

== Package staging with `Install`

Publisher sconscripts typically install headers and libraries into a package directory, then hand
the nodes to `PublishPackage`:

[source,python]
----
Import('env')
import os

package_dir = env['package_dir']  # as configured for the publisher
include_src = os.path.join(library_source_tree, 'include', 'widget')
lib_node = built_library_node      # from an earlier Command / Build step

installed_include = env.Install(os.path.join(package_dir, 'include'), include_src)
installed_lib = env.Install(os.path.join(package_dir, 'lib'), lib_node)

env.Depends(installed_include, installed_lib)
env.Requires(installed_include, installed_lib)

published = env.PublishPackage(installed_include, publisher)
----

`Depends` / `Requires` keep include and library staging ordered with the built library — see
xref:methods/depends.adoc[Depends] and xref:methods/packages.adoc[Packages].

== `InstallAs`

`InstallAs` installs to an explicit destination *file* path (rename on install). Use it when the
basename in the package tree must differ from the source basename. Prefer `CopyFilesAs` when you
are staying inside Cuppa's artefact/`final/` workflows.

== Assets under `final/`

Small doc or CSS trees sometimes call `Install(env['final_dir'], 'clearpool.css')` (or a short
list of files). That is valid; many Cuppa projects use `CopyFiles` for the same job so artefact
paths stay consistent with test output copying. Choose one style per project and stick to it.
