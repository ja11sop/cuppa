= Flags and toolchain methods
:description: Toolchain lookup and mutating compile/link flags

This page covers how you change compiler and linker flags on a Cuppa environment, and how you
look up a registered toolchain. Cuppa's `ReplaceFlags()` / `RemoveFlags()` sit alongside everyday
helpers such as `AppendUnique()` and `MergeFlags()` — one “how do I set flags?” story.

Optional reference (unversioned):
https://scons.org/doc/production/HTML/scons-user/apd.html[SCons user guide — Functions and Environment Methods].
Prefer the examples here for Cuppa projects; the SCons man page examples are often too abstract to copy
into a real `sconscript`.

== Behaviour summary

[cols="1,3"]
|===
| Returns | `Toolchain()` returns a toolchain object; flag helpers mutate `env` (typically return `None` or the env, depending on the call)
| Evaluation | Immediate (configure-time)
| Output paths | N/A
| Progress | No — these calls do not create build-action nodes
|===

== Choosing a helper

[cols="1,3"]
|===
| Call | When to use it

| `MergeFlags()`
| Add GCC-style flag strings (or a flag dict) and let SCons sort them into `CCFLAGS` /
  `CXXFLAGS` / `CPPPATH` / … Cuppa projects often pass a single define string after `BuildWith()`.

| `AppendUnique()`
| Append to a *named* construction variable without duplicating entries — `LIBPATH`, `LIBS`,
  `STATICLIBS`, `SHAREDLIBS`, `CPPPATH`, and so on.

| `Append()`
| Like `AppendUnique()`, but allows duplicates. Prefer `AppendUnique()` unless you know you need
  repeats.

| `RemoveFlags()`
| Strip existing flags that share a Cuppa *flag family* (for example all `-std=` / `-std:` /
  `/std:` dialects) from `CCFLAGS`, `CXXFLAGS`, `CFLAGS`, and `LINKFLAGS`.

| `ReplaceFlags()`
| `RemoveFlags()` then `MergeFlags()` — swap a dialect or option set cleanly (used by `StdCpp()` and
  modules helpers).

| `Toolchain()`
| Look up a registered toolchain by registry key (`clang`, `gcc15`, …) or by
  `toolchain.name()` (build/ABI identity).
|===

== Everyday pattern with dependencies

After `BuildWith()`, projects commonly add defines and library lists before `Build()` / `BuildTest()`:

[source,python]
----
Import('env')

env.BuildWith('boost_package').use_libs(['boost_unit_test_framework'])
env.MergeFlags('-DBOOST_ASIO_NO_DEPRECATED')

env.AppendUnique(SHAREDLIBS=['pthread'])
env.BuildTest('unit_tests', ['tests.cpp'])
----

`BuildWith()` configures include/library paths for a dependency; `MergeFlags()` / `AppendUnique()`
layer project-local options on top. Prefer that order so dependency settings stay intact.

== Replacing a language dialect

`ReplaceFlags()` removes any existing flag in the same family, then merges the replacement.
That is how Cuppa can move from `-std=c++20` to `-std=c++23` (and the MSVC `-std:` /
`/std:` spellings) without leaving a stale dialect on the command line:

[source,python]
----
Import('env')

env.ReplaceFlags(['-std=c++23'])
----

For the high-level dialect API, prefer xref:methods/cxx-dialect-and-modules.adoc[`StdCpp()`] when
that page's tutorial is what you want; it uses `ReplaceFlags()` underneath.

== Looking up a toolchain

[source,python]
----
Import('env')

clang = env.Toolchain('clang')
# or a build/ABI identity such as clang-libc++
----

Toolchain *defaults* (warnings, optimisation, modules flags) are documented under
xref:toolchains.adoc[Toolchains] and the family pages — not duplicated here.
