= MSVC (`vc` / `cl`)
:description: Cuppa MSVC toolchain — Windows platforms, aliases, default flags, modules

[#msvc-toolchain]
== Introduction

https://learn.microsoft.com/en-us/cpp/[Microsoft Visual {cpp}] (MSVC) is Cuppa’s Windows
{cpp} toolchain. Cuppa integrates with SCons Visual {cpp} detection and drives `cl.exe`
under the `vc` / `cl` family names. Coverage instrumentation (`--cov`) is **not**
supported for MSVC.

Upstream documentation: https://learn.microsoft.com/en-us/cpp/[{cpp} in Visual Studio] ·
Compiler options:
https://learn.microsoft.com/en-us/cpp/build/reference/compiler-options-listed-alphabetically[MSVC compiler options].

Names are the generic alias `vc` (SCons default install) plus versioned aliases derived
from the SCons MSVC **toolset** id:

[cols="3,3,4"]
|===
| SCons / VS toolset | Cuppa `--toolchains=` | Notes

| `14.5`
| `vc145`
| VS 2026+ platform toolset *v145*

| `14.3`
| `vc143`
| VS 2022 *v143*

| `14.2` / `14.2Exp`
| `vc142` / `vc142e`
| VS 2019 *v142*

| `14.1`
| `vc141`
| VS 2017 *v141*
|===

The alias drops the dot so CLI names stay short and match the familiar `v145`-style label
(same digit style as `gcc15` / `clang21`).
Capability floors use this toolset `(major, minor)` -- not compiler marketing strings such
as `14.29` / `19.51`.

[source,sh]
----
cuppa -D --dbg --toolchains=vc
cuppa -D --dbg --toolchains=vc145
cuppa -D --dbg --modules --stdcpp=c++20 --toolchains=vc143
----

For selection and listing shared with other families, see xref:toolchains.adoc[Toolchains].
Inspect the live default invocation strings with `--list-toolchains --list-format=verbose`.

Cuppa’s MSVC default is `-std:c{plus}{plus}20`, which already includes concepts and coroutines.
There are no extra MSVC feature switches for those. Modules stay opt-in via `--modules`.

(MSVC has no `c` / `cov` lines).

== Modules (opt-in)

* Floor: toolset **14.2+** (`vc142` and newer)
* Exported interface units: `-interface`, `-TP`, space-separated `-ifcOutput PATH`
* Non-exported partitions (`module M:part;`): `-internalPartition`, `-TP`, `-ifcOutput PATH`
* Consumers: space-separated `-reference name=PATH` (colon-attached forms break on absolute `C:\…` paths)
* BMI extension: `.ifc`
* Header units: `-exportHeader` (+ `-headerName:angle` for system headers); consumers use `-headerUnit` / `-headerUnit:angle`
* `import std`: toolset **14.3+** when STL `modules/std.ixx` is present (compiled with `-interface` / `-ifcOutput`)

See xref:cxx-modules.adoc[{cpp} modules].

== Limitations

* Coverage is not supported for MSVC
* Shared libraries that export module symbols still need `__declspec(dllexport)` (or a `.def`) so the linker produces an import library — cuppa does not invent DLL exports from `export` alone
