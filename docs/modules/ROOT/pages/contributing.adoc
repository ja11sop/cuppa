= Contributing
:description: How to contribute to the cuppa repository — validation, versioning, and releases

This section is for people changing **cuppa itself** (the public repository), not for projects that
only *consume* cuppa as a build tool.
Consumer documentation starts at xref:install.adoc[Installation] and xref:quickstart.adoc[Quickstart].

Start with xref:contributing/overview.adoc[Contributing overview] for the development workflow.
This hub provides the detailed pull-request rules and routes you to versioning, report patterns,
linting, integration tests, and releases.

== Documentation writing conventions

Antora pages under `docs/modules/ROOT/pages/` follow the **Placeholders and omissions**
section of repository `AGENTS.md`. Short form:

[cols="2,3,4"]
|===
| Intent | Write | Avoid

| Editorial cut (excerpt, truncated status text)
| Three ASCII periods `...`
| Unicode ellipsis (U+2026)

| Named fill-in
| `` `<abi>` ``, `` `<storage>` ``, `` `<kwargs>` ``
| Anonymous `` `<...>` `` when a real name exists

| Anonymous fill-in (last resort)
| `` `<...>` ``
| Stacked `` `<...>/<...>` `` path holes; inventing placeholders inside CLI samples
|===

Colour roles (`[.cuppa-ph]`, `[.cuppa-ph-focus]`, `[.cuppa-ph-context]` in supplemental
`cuppa.css`) are optional emphasis in prose — angle brackets are the primary signal.
Copy-paste shell listings stay plain. Console fragments under `partials/samples/` may still
show ``…`` when they mirror CLI truncation; do not “fix” those to doc placeholders.

`python -m scripts.check_docs_placeholders` (included in `check_docs_urls`) fails the gate
when authored AsciiDoc or `AGENTS.md` reintroduces U+2026 outside an explicit “do not use”
teaching line.

== Previewing the documentation site

For day-to-day edits on the current branch, from `docs/`:

[source,shell]
----
npm ci
npm run build
----

That builds a single Antora version from the checkout (`next`) into `_docs_build/site/`.

The public GitHub Pages site is multi-version: the latest release tag as stable
(under `/cuppa/latest/<page>`) plus this checkout as prerelease `next`. To build that
locally (requires release tags in the clone):

[source,shell]
----
npm run build:site
----

To also generate agent-oriented Markdown (`llms.txt`, `llms-full.txt`, and per-page
`.md` under the `latest` tree), install `pandoc` and Python `lxml`, then:

[source,shell]
----
npm run build:site:all
----

The published product index for agents is
https://ja11sop.github.io/cuppa/llms.txt[llms.txt] on the docs site.
Repository `AGENTS.md` targets contributors changing cuppa itself (CI, commits,
private-name rules) and is not a substitute for that index.
