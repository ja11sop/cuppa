= {cpp} Profiles
:description: Opt-in {cpp} Profiles with cuppa (--cxx-profiles / --cxx-profiles-enforce)

include::partial$cxx-profiles/attribute-markers.adoc[]

In this guide you will learn what ISO {cpp} **Profiles** are aiming at, what cuppa
supports today, how to enable them with a Profiles-capable Clang, and where the
feature may go next.

Cuppa's **BuildProfile** (`env.BuildProfile(…)`) is a different concept: named
build-time env tweaks. This page is only about the **language** Profiles
framework (`{cxx-a-profiles-ellipsis}`, experimental `-fprofiles`).

Profiles are **opt-in** (`--cxx-profiles` / `--cxx-profiles-enforce=` or
`env.CxxProfiles()` / `env.CxxProfilesEnforce(…)`). Builds that do not pass those
flags are unchanged.

== State of play (today)

[cols="2,3"]
|===
| Area | Status

| Standardisation
| Framework and specific profiles are under active WG21 / SG23 discussion (see <<papers>>). Designators and wording are still evolving; treat paper names as directional.

| Compilers
| **{cpp} Alliance** experimental Clang (Profiles archive) accepts `-fprofiles` and has been smoke-tested with `{cxx-a-profiles-enforce-std-init}`. Distro / upstream Clang and GCC/MSVC do **not** implement this surface in cuppa.

| Cuppa CLI
| `--cxx-profiles` enables the framework when the selected toolchain probes successfully for `-fprofiles`; otherwise the build stops with a clear error. `--cxx-profiles-enforce=<designators>` implies `--cxx-profiles` and applies those designators to every {cpp} translation unit (see <<how-cuppa-enables>>).

| Verified designator
| **`std::init`** (initialization profile; related papers P3402 / P4222). Do not assume other names work on Alliance Clang until you have tried them.
|===

== Enabling Profiles

. Obtain a Profiles-capable Clang ({cpp} Alliance release archive) and register it with cuppa, for example:

```
cuppa -D --toolchain-archive=https://github.com/cppalliance/clang/releases/download/profiles-2026-08-07-27/clang-profiles-linux-x86_64.tar.gz
```

Session names look like `clang24_profiles_2026_08_07_27`. See xref:toolchains.adoc[Toolchains] and xref:toolchains/clang.adoc[Clang].

. Build with the framework and (optionally) session-wide enforce:

```
cuppa -D --dbg --toolchains=clang24_profiles_2026_08_07_27 --cxx-profiles --cxx-profiles-enforce=std::init
```

`--cxx-profiles` alone turns on `-fprofiles` so attributes in your sources are recognised.
`--cxx-profiles-enforce=std::init` also asks cuppa to enforce that designator on every {cpp} TU.

You can put enforce in source yourself instead of (or as well as) the CLI:

```cpp
[[profiles::enforce(std::init)]];

int main()
{
    int Value = 0;
    return Value;
}
```

[#how-cuppa-enables]
== How cuppa enables Profiles today

=== Framework flag

When `--cxx-profiles` is set, cuppa asks the toolchain for enable flags. On Clang that
means probing the driver with `-fprofiles` and caching the result. A successful
probe appends `-fprofiles` to `CXXFLAGS`. An unsuccessful probe raises
`StopError` (no silent no-op). GCC and MSVC report unsupported.

Major version alone is not enough: ordinary `clang24` fails the probe; a Profiles
archive succeeds.

=== Enforce: native flags or `-include`

For `--cxx-profiles-enforce=a,b`:

1. If the toolchain returns native enforce flags from
   `profiles_enforce_flags` (none known on Alliance Clang today), those flags are
   appended.
2. Otherwise cuppa writes a small generated header under the build tree, for example
   `_build/.../profiles/enforce_std_init.hpp`, containing:

```cpp
[[profiles::enforce(std::init)]];
```

and compiles each {cpp} translation unit with `-include <that header>`.

`-include` is processed like a leading `#include`: the preprocessor tracks file and
line with linemarkers, then resumes your primary source at line 1. Diagnostics in
your `.cpp` keep their original line numbers. Cuppa does **not** rewrite files in
your source tree.

If a translation unit already contains a `{cxx-a-profiles-enforce-ellipsis}` attribute in
its preamble, cuppa **does not** add a second enforce via `-include`. Instead it
writes a compiler-facing merged view under the build tree (still without touching
your sources): CLI designators are appended to the attribute's list. For example
`{cxx-a-profiles-enforce-foo}` with `--cxx-profiles-enforce=std::init` becomes
`{cxx-a-profiles-enforce-foo-std-init}` in that view. An empty placeholder
`{cxx-a-profiles-enforce-empty}` in source receives the CLI designators the same way.
The merged view is prefixed with `#line` so diagnostics still cite your original
file. When the source attribute already lists every CLI designator, cuppa compiles
the original file unchanged.

Optional methods (same env keys as the CLI):

* `env.CxxProfiles()` — force the framework on for that env
* `env.CxxProfilesEnforce('std::init')` — set enforce designators and activate

[#violation-inventory-report-cxx-profiles-report]
=== Violation inventory report (`--cxx-profiles-report`)

When you need a browsable inventory of Profiles diagnostics before fixing sources,
pass `--cxx-profiles-report` together with `--cxx-profiles` or `--cxx-profiles-enforce=`.
Cuppa captures diagnostics during the build and writes HTML plus JSON under
`<artefacts-root>/cxx-profiles/` (default `_artefacts/cxx-profiles/`) at the end of the
session (`sconstruct_end`). The construction `env` exposes `artefacts_root` and
`abs_artefacts_root` (US aliases `artifacts_root` / `abs_artifacts_root`; set via
`--artefacts-root=` or `--artifacts-root=` alongside `--build-root=`).

Pair with `--cxx-disable-error-limit` so the compiler does not stop after its
default diagnostic cap. The report is read-only — it does not rewrite sources.

==== Inventory mode (keep-going builds)

``--cxx-profiles-report`` and ``env.CollateCxxProfilesIndex()`` enable *inventory mode* for the
session. Cuppa prepends SCons keep-going (``-i``) when you have not passed it already, so
Profiles violations on one translation unit do not stop the rest of the tree from compiling.
Progress ordering still reaches ``#SconstructEnd``, and the session index is written at the end
of the build (with a fallback flush when capture is non-empty but the normal hook did not run).

On the console, profile-shaped diagnostics keep an **Error** label but use warning colours so you
can tell them apart from ordinary compile failures (which stay red). Inventory mode tallies
*non-profile* compile errors separately: the session index is still written, but cuppa exits
**non-zero** when that tally is non-zero so CI stays honest. A session with only Profiles
violations exits **zero** once the index is written.

You do not need to pass ``-i`` manually for inventory runs — cuppa adds it when inventory mode
is active.

[source,bash]
----
cuppa -D --dbg --toolchains=clang24_profiles_2026_08_07_27 \
  --cxx-profiles --cxx-profiles-enforce=std::init \
  --cxx-disable-error-limit --cxx-profiles-report
----

The session index opens on an **Overview** tab when context capture is enabled
(`--cxx-profiles-report-context=full`, the default). Start with
xref:cxx-profiles/report-introduction.adoc[Introduction] for generating the report, offline regen,
JSON export, and shared vocabulary (**Union Refs**, **Peak Refs**, **Build Refs**). Use
xref:cxx-profiles/report.adoc[Violation report reading guide] for tab-specific guides.
The Overview tab summarises inventory, codebase reach, violation density, rule
concentration, and per-profile rule matrices — see
xref:cxx-profiles/report-overview.adoc[Overview tab]. Multi-build roll-ups on **Violations
By-Rule** and **By-File** are documented on xref:cxx-profiles/report-by-rule.adoc[By-Rule] and
xref:cxx-profiles/report-by-file.adoc[By-File]; per-build slices on
xref:cxx-profiles/report-by-build.adoc[By-Build]; per-scope pages on
xref:cxx-profiles/report-by-sconscript.adoc[By-Sconscript].

Other index tabs list roll-ups **By-Rule**, **By-File**, and **By-Build**, plus per-sconscript
scope rows under **Violations By-Sconscript**. Per-scope HTML pages show that build's inventory
only (plain numbers; **Build Refs** replaces **Peak Refs** — see
xref:cxx-profiles/report-introduction.adoc#scope-metrics[scope metrics]). Session union totals on
the index deduplicate violation identities across builds; **Union Refs** uses row peaks per
identity, not a naive sum of every variant's compile inventory.

Optional flags:

* `--cxx-profiles-report=` *path* — explicit report directory (or index file stem)
* `--cxx-profiles-report-root=` *dir* — rebase project-owned paths for display and links
* `--cxx-profiles-report-link-style=local|gitlab|github|remote` — Profiles-only source link override (see link-style precedence below)
* `--cxx-profiles-report-context=full|rules-only|off` — Overview `context` in JSON/HTML (`full` default; `rules-only` omits tier 1/2 denominators; `off` hides Overview context)

==== Interpreting the Overview tab

xref:cxx-profiles/report-overview.adoc[Violation report — Overview tab] explains the Violation totals,
Codebase reach, and Violation density cards, the rule concentration table, and profile matrices.
Each Overview summary card and section heading links to the matching section on that page.

==== Source link styles

Profiles HTML uses the same link-style vocabulary as test reports (`local`, `gitlab`, `github`, `remote`).
Pass xref:cli-reference.adoc#reports-link-style[`--reports-link-style=`] on the cuppa command line
to set source links for every report kind the session emits (test HTML, Profiles HTML, and future
coverage links). That lets one sconscript build on GitHub Actions or GitLab CI without editing
`link_style=` in each method call. Use `remote` when violations span location dependencies on
another host (GitHub project + GitLab dependency, or mixed GitHub orgs).

When both are present, `--cxx-profiles-report-link-style=` overrides `--reports-link-style=` for
Profiles output only (and for `.cuppa-reports` manifest matching on clean).

==== Offline regeneration (template iteration)

To re-render Profiles HTML without recompiling, use the maintainer script (not a cuppa
`AddOption` flag):

[source,bash]
----
python -m scripts.regenerate_profiles_report \
  --from-json _artefacts/cxx-profiles/cxx-profiles-index.json
----

Omit `--sconstruct-dir` to take project paths and link style from JSON ``metadata``. Source files
must exist on disk for ``by-source/`` pages unless ``--skip-source-pages`` is set.

[cols="1,3"]
|===
| Script flag | Meaning

| `--from-json`
| Interpret the positional argument as `cxx-profiles-index.json` (recommended)

| `--sconstruct-dir`
| Project root; default: cwd, or JSON metadata with `--from-json`

| `--artefacts-root`
| Same meaning as cuppa `--artefacts-root` (default `_artefacts`; US alias `--artifacts-root`)

| `--artifacts-root`
| US spelling alias for `--artefacts-root`

| `--report-dir`
| Output directory (default: `<artefacts-root>/cxx-profiles/`)

| `--link-style`
| Source links for this regen run; default: JSON metadata or `local` (alias: `--reports-link-style`)

| `--reports-link-style`
| Same as `--link-style`

| `--cxx-profiles-report-link-style`
| Profiles-only override for this regen run

| `--skip-source-pages`
| Omit `by-source/` marked-up pages

| `--anonymised`
| Regenerate from anonymised JSON; implies `--skip-source-pages` and suppresses file/repo hrefs
  when `metadata.anonymised` is set

| `--write-json`
| Rewrite `cxx-profiles-index.json` after re-render

| `--summary`
| Print capture replay summary (capture replay only)
|===

Full regen workflow, JSON-for-CI notes, and anonymised sharing:
xref:cxx-profiles/report-introduction.adoc#offline-regeneration[Introduction — offline regeneration]
and xref:cxx-profiles/report-introduction.adoc#sharing-anonymised[Sharing an inventory (anonymised JSON)].

Capture replay (`capture.txt` without `--from-json`) remains legacy — parallel `tee` output can
mis-attribute scope; prefer JSON when a live build already wrote `cxx-profiles-index.json`.

Generated report paths are recorded in a project-local ``.cuppa-reports`` manifest (JSONL, one
entry per invocation). When you run ``--clean`` or ``--remove-builds`` with the same report
destination and link options on the command line, cuppa removes matching manifest entries and
deletes the listed files. ``--remove-builds`` alone does not remove reports under
``_artefacts/`` (or legacy ``_artifacts/`` when that tree is still in use).

=== Full diagnostic lists (`--cxx-disable-error-limit`)

Profile enforce checks can emit many diagnostics; compilers stop after a default cap.
Pass `--cxx-disable-error-limit` to append toolchain-specific unlimited flags
(Clang `-ferror-limit=0`, GCC `-fmax-errors=0`). MSVC `cl.exe` has no supported
equivalent (it stops with fatal C1003 after an internal cap). Pair with
`--cxx-profiles-enforce=` when you need the complete violation set for reporting or
batch fixing. Optional method: `env.CxxDisableErrorLimit()`.

[#future]
== What may come next

These items are intentional follow-ons, not commitments for the next release of
the feature:

* **More designators** as Alliance Clang (and eventually other compilers) implement
  them; cuppa passes designator strings through unchanged.
* **Native enforce command-line flags** when a compiler provides them; the
  `profiles_enforce_flags` hook is already reserved so `-include` can give way to
  the driver's mapping.
* **Carve-outs** for paths that should not receive session enforce (build policy).
* **Modules + `profiles::require`** once import-site wiring is worth the complexity.

Design detail and refusal rules: link:https://github.com/ja11sop/cuppa/blob/master/design/archive/cxx-profiles.md[`design/archive/cxx-profiles.md`]
and issue link:https://github.com/ja11sop/cuppa/issues/127[#127].
